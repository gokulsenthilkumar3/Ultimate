# Family Connect compact workspace

Date: 7 November 2026. Scope: Ultimate web UI and bounded Family query filters. No desktop packaging, database migration or cloud deployment is included. The user explicitly retained editor add/connect permissions.

## Implemented

- A compact heading and sticky tree context replace the repeated hero, identity card and large statistics. Tree, private Me marker, session, role and totals share one context bar across six tabs.
- The tree uses React Flow with zoom/pan/pinch, minimap, fit, center on Me, authorized search-to-focus and a DOM people list. Selecting a node opens a profile drawer. A renderer error boundary offers a bounded list rather than a blank canvas.
- Add Person uses two desktop columns and one mobile column. Optional profile/branch fields remain collapsed; choosing an anchor enables a connection without a redundant checkbox. Required searchable pickers reject typed names until an actual result is selected. Existing-person connection previews identify both people and the direction.
- The private Me switch explains the current selection. It does not change the login, grant access or claim an account. The backend retains the one-marker-per-account-per-tree contract and atomic person/connection/Me transaction.
- Profile actions prefill Add their relative, memory and milestone forms. Relationship rows are scannable, and profile memories/timeline load only when selected. Forms keep Save/Cancel in a non-scrolling modal footer.
- People offers living/deceased filters, search and grid/list. Timeline offers person/type filters. Backend filter builders validate enums and preserve tree scope. File queries accept a scoped person filter.
- Memories has private-photo metadata cards and an existing original-image lightbox; it does not yet have generated thumbnails or a true photo masonry feed. Uploads accept a reviewed single file up to 10 MB with drag/drop; there is no measured transfer-progress percentage.
- Vault identifies the actual tree-level sharing boundary. It explicitly says per-document permissions and encryption are not configured. No fake lock-based encryption claim, sharing count or missing file size is displayed.
- Admins can explicitly save an account role from Access and use the invite form. Editors/family heads retain add/connect and record maintenance; viewers receive read controls. The API remains the authorization boundary.

Source owners: `growthtrack-ultimate/src/domains/family/`, shared optional primitives in `src/domains/native/ModuleUI.jsx` and `src/components/ui/Modal.jsx`, shared token-based styles in `src/domains/native/native-modules.css`; backend `Family Connect/familyconnect/backend/src/services/recordFilters.ts` and consuming controllers. ## Remaining architecture roadmap

1. **Persistence and integrations:** durable audit, outbox with idempotent consumers/retries, explicit profile/deletion reconciliation, soft-delete policy and relationship provenance/status. Calendar/Tasks/HR automation must be opt-in and reviewed; a family relationship or cross-module link grants no financial/HR permission. Private Me and verified account claims remain separate concepts.
2. **Vault:** file metadata/object split, per-document ACLs and download audit; AWS/Azure-compatible storage adapter, TLS, managed encryption, private credentials and backup/restore verification. Client-side E2EE additionally requires key sharing, recovery and revocation design. Server OCR/RAG cannot silently decrypt E2EE files; use client processing or explicit scoped consent. Thumbnail workers precede a large private-photo masonry feed.
3. **Database authorization:** evaluate PostgreSQL RLS with a restricted app role, authoritative actor context set transaction-locally and pool isolation tests. Owners normally bypass RLS; merely enabling policies does not establish tenant isolation. See [PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html). Read replicas must not authorize recently revoked access from stale ACLs. No RLS migration has been run.
4. **Genealogy scale:** measure recursive ancestor/descendant and shortest-path queries before adding closure/materialized paths. Multiple parentages form a DAG; a single `ltree` path is not a complete model. Add duplicate review/merge, relationship provenance and biological/adoptive/guardian distinctions without overloading display labels. Benchmark actual large-tree rendering before choosing Canvas/WebGL.
5. **Interchange/jobs:** GEDCOM import preview, validation, round-trip export and bounded background processing; treat media paths, external URLs and archive extraction as untrusted. Follow the [official GEDCOM specifications](https://gedcom.io/specs/). Add queue-based thumbnails/OCR/PDF exports only with bounded resource budgets.
6. **Collaboration/intelligence:** reviewed profile claims and suggested edits, concurrency/version conflict handling, real-time presence; private-data retrieval authorization and explicit AI consent. No remote OCR/face recognition/RAG service is enabled by this UI change.
7. **Lifecycle:** reviewed successor-admin process rather than assuming inactivity proves death; erasure/anonymization and audit-retention policy; authorized archival exports. Cached records must never survive logout, account changes or a permission denial. No new offline-cache guarantee is introduced.
8. **Operations:** AWS or Azure later, provider-independent configuration now. Managed PostgreSQL/pooling, private networking, backup/PITR and restore drills remain pending. Consumer/provider contract testing and staged migration validation precede any cutover. No cloud credentials, provisioning, production data migration or compliance claim is included.
