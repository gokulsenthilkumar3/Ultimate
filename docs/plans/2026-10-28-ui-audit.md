# Desktop UI audit and fixes

Scope: the isolated GrowthTrack admin design demo, its 65 pages and 201 page/tab destinations. The subsequent [approved real-app UI implementation](2026-10-28-production-ui.md) has 200 separate targeted production checks. This audit does not claim that the separate customer apps or the live Ultimate UI have been redesigned or visually approved.

Status: the preview build and **989 automated checks pass** after the source/interaction audits and the supplied-proposal implementation, including both themes and densities. Browser visual verification remains pending because the available computer-use connection still returned no browsers or apps. No screenshots or pixel-layout pass are claimed. The latest [UI system impact analysis](2026-10-28-ui-system-impact.md) records dependency reach, ownership, the supplied 3D architecture and synthetic scale evidence.

## Issues corrected

| Area | Issue found | Correction and evidence |
| --- | --- | --- |
| State across views | Changing tabs remounted the page and discarded local selections/edits | Keep page identity across tabs; regression checks retain task state and selected Forex pair/period |
| Tasks | Overview quick-add saved tasks under Overview | Route new tasks into the shared Tasks workspace; test creates from Overview and finds the task in Tasks |
| Notes | Clicking different notes still showed fixed sample text; editor drafts disappeared | Select the actual note, show its body, and keep drafts in session state across tabs and navigation |
| Customer support | Closing a profile discarded saved support notes | Store notes with the session's customer record; close/reopen regression verifies the note remains |
| Customer statuses | Invited/inactive accounts could display success styling | Use an explicit shared status mapping; inactive, invited, incomplete and disconnected states remain neutral |
| Customer tab navigation | Profile tabs lacked complete keyboard behaviour | Add tab/panel associations, roving focus, and arrow/Home/End support |
| Dialogs | Background scrolling and focus restoration were unreliable | Lock scrolling with reference-counted overlays; focus the active dialog content and restore its opener on close |
| Mobile navigation | Offscreen links remained focusable; drawer did not contain focus | Apply inert/hidden states, trap drawer focus, support Escape and restore the menu trigger |
| Navigation resizing | An open drawer could reappear after desktop/mobile resizing | Clear drawer state when returning to desktop; regression covers the round trip |
| Sidebar | Child pages lost their active group and Personal Finance was hard to find | Highlight the active parent, add the finance destination, and keep module scrolling separate from footer controls |
| Search | Email matches could appear with a contradictory “no results” message | Use the same normalised result set for matching and empty-state decisions |
| App discovery | Existing names such as NiftyLens did not find the renamed portal module | Search aliases, area names and views as well as page titles |
| Forms | Whitespace-only names failed silently; duplicate customer records were accepted | Show inline validation and reject duplicate email/product combinations in the sample directory |
| Empty tables | A clear action could leave the actual status filter applied | Distinguish empty source views from empty search results and clear the relevant filter |
| Customer sorting | “Last active” sorted display strings alphabetically | Sort relative activity chronologically; verify oldest/newest order in the directory |
| Calendar boundaries | The crossing week could save an event as “32 October” | Use UTC date keys for actual calendar dates, month/year transitions and leap years |
| Calendar events | New events were not displayed on the date or agenda | Render session events from the same event collection in both views |
| Charts | Date labels stayed on the same range and market axes used unrelated counts | Compute labels for the chosen period, scale market charts around the selected quote, and align illustrative bands with the series |
| Portfolio | Allocation and history tabs showed the market watchlist | Give holdings, sector allocation and value history distinct portfolio layouts |
| Goals | Completed/archived views relabelled unrelated cards | Filter the appropriate records and derive counts from the same sample collection |
| Shopping | Planned/purchased tabs displayed all items | Apply the selected status filter and verify both views |
| Focus timer | Start only changed a label | Run a local countdown with pause, resume, completion and reset behaviour |
| Page actions | Public, informational and analytics pages offered unrelated add-record actions | Use page-specific actions; omit actions where no record creation belongs |
| Loading failures | A failed lazy page could take down its workspace | Isolate page errors, provide a recovery screen, and reset the boundary when moving to another view |
| Review accuracy | A loading page could be approved as populated; old or malformed approvals survived design changes | Wait for the page to render before enabling approval; validate saved records against page, tab, theme, state, density, viewport and revision v5 |
| Text and controls | Many captions, inputs and controls were too small | Raised 178 undersized type declarations, enlarged primary controls and mobile targets, and made narrow tables/charts locally scrollable |
| Colour | Several light-theme semantic colours fell below the selected text contrast threshold | Adjusted muted, danger, amber, peach, lilac and sand text colours; token checks cover both themes |
| Responsive layout | Review toolbar, theme choices and long profile/catalog text could exceed narrow widths | Use a two-column mobile toolbar, flexible theme tiles and wrapping text; reserve space below the fixed review bar |
| Finance records | Added entries lived in a generic footer and did not change the native ledger or totals | Use typed amount/date/direction fields and a shared ledger for transactions, overview and analytics; retain cents and sort recent records by date |
| Budgets | Category totals and history did not describe the displayed data | Calculate totals from the current categories; show a separate historical month and preserve its values |
| Subscriptions | Archived tabs relabelled active sample records; renewal totals were unrelated | Filter actual active/archive states and 30-day dates; exclude archive costs and share new plans with recurring trends |
| Shopping totals | Added amounts and statuses did not affect the list or counters | Collect amount, category and purchase status; derive each filtered list and its totals from the same records |
| SIP views | Projection and comparison tabs repeated the same summary | Add distinct annual projection and assumption-comparison tables that respond to the calculator inputs |
| Family membership | Added members did not join the native family view | Show new unlinked members, update the count and timeline, and avoid assigning invented relationships |
| Family calendar | Family events and workspace calendar were inconsistent | Share seeded and session-added family events, including their dates, with both layouts |
| Family vault | The family view included unrelated workspace documents | Filter files by Family Connect ownership and derive the vault count from the same scope |
| Timer navigation | Leaving the page reset the timer; throttled ticks could drift | Keep the session at the shell and calculate remaining time from a deadline; retain pause/resume across navigation |
| Preferences | Information density reset on reload | Save the selection locally and restore it when reopening the demo |
| Form context | Browser history could leave a form open on another page; product-specific forms allowed another product | Close overlays on route changes, capture entry origin, and limit the customer product selector to its directory |
| Dialog boundaries | Clicking dialog padding or the scrollbar could dismiss it | Only dismiss an actual outside click, using the dialog rectangle |
| Long content | New member names and category labels could force flex children beyond their panels | Allow text to wrap in panel titles, progress labels, timeline articles and event rows |
| Large tables | All supplied records mounted at once | Paginate the shared table at 25 rows by default, cap selectable pages at 100, sort before slicing, reset/clamp pages and preserve empty-state recovery |
| Density approval | Comfortable approval also appeared approved in compact mode | Include density in the review key and validate stored records against the revised schema |
| Review progress | One approved tab could imply that a page had been reviewed; scopes were mixed | Show approved views and fully completed pages only for the exact current scope; add area/status filters and next-unapproved navigation |
| Review navigation | A catalog jump from an error preview returned to populated content | Preserve the selected preview state during review navigation |
| Feedback context | Resizing while writing feedback could attach it to another viewport; whitespace-only feedback was accepted | Freeze the target on opening, validate a trimmed description and retain inline errors |
| Review storage | Repeated metadata inflated large review histories; quota warnings were transient | Compact stored records with validated restoration, retain full readable exports and show a persistent session-only warning on failure |
| Physique workspace | All editor/target tabs reused a static silhouette and fixed measurements | Introduce an independent lazy screen, Current/Goal controls, debounced schematic outline, comparison/target/history views and explicit local snapshots |
| Physique boundaries | Drafts, saved history and portable geometry could be confused | Keep drafts independent from saved snapshots, label sample JSON and keep unavailable GLB export disabled |
| Style ownership | Old Physique selectors remained in the shared stylesheet | Move active stage styling into the lazy domain stylesheet and remove obsolete shared rules |

## Remaining visual gate

Inspect the rendered pages at 1024, 1280, 1440 and 1920 pixels in both themes, plus a 390-pixel fallback. Verify actual text wrapping, clipping, table/chart scrolling, native dialog and drawer behaviour, keyboard focus, zoom, reduced motion and long-content cases. Pay particular attention to the larger text sizes and fixed review toolbar. Record each reviewed page/tab/theme/state/viewport in the demo and export the review.

These visual checks require a connected browser. Until they are completed, the correct status is **automatically checked and ready for visual review**, not flawless or visually signed off. Production migration and real customer API integration remain governed by the [redesign plan](2026-10-28-admin-redesign.md).
