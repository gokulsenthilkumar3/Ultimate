# Sign-out, sub-tabs and login refinement

30 October 2026. The user requested a more finished “ultra UI” treatment, especially for sign-out, sub-tabs and login. This continues the established character theme in Ultimate's existing React implementation; no additional UI framework or hosted deployment is introduced.

## Implemented surfaces

- **Sign-out:** a dedicated Sunny illustration, a readable draft summary, explicit keep/remove radio cards and a focused action area. Keep is selected on every opening. Removal is available only when drafts were successfully inspected and exist. Busy state disables all choices, cancel, close, Escape and backdrop dismissal. Rejected sign-out leaves the account and drafts intact and supports retry. Successful sign-out reports kept/removed/cleanup-failed outcomes on login.
- **Sign-out transition:** the result stays in App state while the protected route hands off to login, avoiding a navigation-state race. Login stays disabled while acknowledged sign-out still has draft cleanup pending. The captured owner ID remains the deletion scope, and the previous route's path, query and unconsumed fragment remain available for the next sign-in. Only the existing server acknowledgement and existing local draft functions perform account/data operations.
- **Sub-tabs:** existing keyboard-native Tabs now have numbered accent chips and a measured selection indicator that tracks the selected button without replacing it. Resize observers update its dimensions and disconnect on cleanup. Horizontal, RTL, vertical, automatic/manual activation, disabled tabs and caller-owned handlers retain their contracts. Underline remains an explicit variant.
- **Module shortcuts:** a separate horizontal link navigation provides access to modules in the current area. It uses real canonical router URLs, saved module order, deployment base paths and `aria-current`, distinct from tab-panel semantics. Overflow stays within its navigation strip.
- **Login:** a framed character scene, small illustrated captions, account-section hierarchy, leading field icons, an embedded accessible password reveal, and dismissible sign-out feedback. Field-focus artwork, safe return destinations, error correction and duplicate-submission handling remain available. The illustration never reads credential contents.
- **Shared details:** solid semantic toast cards, rounded dialogs, clearer button states, customer-admin links, highlighted sign-out entry and an Apps Suite that uses the current light/dark semantic surfaces rather than hard-coded legacy dark cards.

## Motion and ownership

The same global pause, system/app reduced-motion preference, viewport observers and document visibility rules control the character and interface treatment. Moving tab highlights use CSS transitions; functional choices never wait for an animation. New styles extend the existing canonical component, shell and domain sheets. The independent FinSync/OxFin customer applications, isolated demo fixtures, model assets, database schema and service boundaries are unchanged.

## Verification scope

New checks cover explicit draft choices and reopening defaults, no deletion after failed sign-out, pending-request locking, completion notices, retained return destinations, pending-cleanup login blocking, focused tab identity and observer disposal, saved shortcut ordering/base paths and toast deduplication/actions. All account and draft writes in tests are mocked.

Final results: 122 targeted production checks passed across 17 suites in focused runs; all 1,005 isolated design-demo tests passed; final Ultimate/design builds and TypeScript passed; six gateway/proxy checks passed; generated design adapters and 23 application READMEs checked successfully. UI impact and handoff artifacts were regenerated with rendered sign-off still pending.

The sign-out integration cases specifically verify that keeping drafts performs no removal, removal runs only after successful sign-out and uses the captured owner, rejection retains the dialog for retry, cleanup failure is reported on login, and pending cleanup blocks another sign-in. A controlled deferred response exposed the completion-message navigation race during implementation; retaining the outcome through the existing route guard resolved it. The shortcut tests check actual URLs rather than treating route navigation as tab panels.

The supported computer-use inventory still reports no connected browser or native UI. Automated component checks and HTTP readiness do not establish rendered desktop/mobile coverage, visual approval or live owner sign-in. Existing historical model-preview hash drift is outside this change.
